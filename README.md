# keydrill

Learn and drill Hyprland bindings, Neovim, and terminal commands — plus raw
typing speed. Stdlib Python, no dependencies, no network access.

```bash
python3 ~/Projects/keydrill/keydrill.py
```

Opens `http://127.0.0.1:8777/`. Ctrl-C to quit.

```
--port N     listen somewhere else (default 8777)
--no-open    don't launch a browser
```

## Requirements

- **Python 3** — stdlib only, nothing to install
- **Hyprland** — for the Hyprland deck. Reached through `hyprctl`; the chord
  capture needs Omarchy's Lua config API (`hl.define_submap`)
- **Neovim** — optional. Without it the motion deck is skipped and the app
  says so at startup; the keymap deck comes from your own config

Everything else degrades rather than crashes: a deck that can't load is left
out of the deck list.

## Two loops over the same material

**Learn** introduces an item with the answer visible and has you perform it,
then hides the answer and asks again. Two clean recalls graduates it. Getting
it wrong drops you back to seeing the answer. Only 5 items are in flight at a
time — a batch you can hold in your head beats a list you can only skim.

**Drill** is pure recall, weighted toward what you get wrong or answer slowly.

Every deck supports both. Progress is per item, so learning a binding in one
mode counts in the other.

At the recall stage the answer is hidden, but the hint stays visible and
**Show answer** is always there. Using it drops the item back to the guided
stage rather than quietly counting as learned — peeking is not knowing.
**Skip** rotates the item to the back of the queue.

## Decks — 370 items

| Deck | Items | Source | You answer by |
|---|---|---|---|
| Hyprland | 128 | `hyprctl -j binds`, live | pressing the real chord |
| Neovim keys | 136 | your LazyVim config, live | typing the sequence |
| Neovim motions | 35 | `data/nvim_motions.json` | typing keys into a real nvim |
| Terminal | 71 | `data/terminal.json` | typing the command |

Hyprland bindings are grouped into lessons by parsing Omarchy's own source
files (`tiling.lua`, `applications.lua`, …), since `hyprctl` doesn't report
which file a bind came from.

Some prompts have more than one right answer — Omarchy binds both
`SUPER+SHIFT+RETURN` and `SUPER+SHIFT+B` to "Browser", and LazyVim
double-binds several of its own. Every chord sharing a description is accepted
and all of them are shown, so a valid answer is never marked wrong. Neovim keymaps are grouped by leader prefix —
`<leader>f…` is "find", `<leader>g…` is "git", and so on.

Both live decks re-read on startup, so they follow your config rather than a
snapshot. `POST /api/reload` refreshes without restarting.

The Hyprland and Neovim-keys counts above are **whatever this machine has** —
128 and 136 here. Clone this somewhere else and you get that machine's
bindings instead. Only the 35 motions and 71 terminal commands are fixed, since
those ship as JSON in `data/`.

### Neovim motions run in real nvim

No vim emulator. Your keystrokes are fed to an actual headless `nvim -u NONE`
via `feedkeys()`, and the resulting buffer is compared against the goal. It
cannot disagree with real vim, because it *is* real vim. Roundtrip is ~10ms.

Keys travel through the environment rather than being interpolated into an Ex
command line — a `|` or `"` in your keystrokes would otherwise split or
comment out the command. Cursor-only motions additionally check final position.

Every exercise's expected result was generated by running its own solution
through nvim, then verified solvable. Indent width is set to 2 spaces to match
LazyVim rather than vanilla's 8-wide tabs.

Type the motion into the capture box: `Ctrl+Enter` runs it, `Ctrl+Backspace`
clears. Escape is captured as a real `<Esc>`, so `ciwnew<Esc>` works as typed.

### Terminal answers are compared, never executed

Nothing you type in terminal mode is run. Answers are matched against a list of
accepted forms after normalising whitespace and quote style, so
`tar -czf out.tar.gz dir` passes where `tar czf out.tar.gz dir` is canonical.

## Typing mode

Four sources: `symbols`, `lua`, `shell`, `prose` — the first three dense with
the config punctuation (`{} [] | $ ~ / \`) that KTouch's English course never
touches. Per-character miss rates accumulate; once a character has 5+ samples
above a 2% miss rate, drill text biases toward lines containing it.

## Capturing SUPER chords

Hyprland normally consumes `SUPER + W` before any application sees it. During a
chord drill, keydrill enters a **submap** named `keydrill` whose only binding is
`ESCAPE`. Everything else falls through to the browser.

Four independent ways out, all tested:

| Situation | What releases it |
|---|---|
| You press ESC | The submap's own binding, at the compositor |
| You leave the deck or tab | `POST /api/submap/exit` |
| Browser tab dies | Watchdog — no heartbeat for 3s, server drops it |
| Server signalled | `SIGTERM`/`SIGINT`/`SIGHUP` handler + `atexit` |

Only `kill -9` escapes all four, and even then ESC still works — the binding
lives in Hyprland, not in this process. Nothing is written to your Hyprland
config; the submap is defined at runtime and disappears when Hyprland restarts.

Note that `hyprctl keyword` does not work under Omarchy's Lua parser. Runtime
config goes through `hyprctl eval` with the `hl.*` API instead.

## Answers stay on the server

Drill mode never sends the answer to the browser. Chords, commands and key
sequences are all judged by `POST /api/check`, so there is nothing to read out
of devtools mid-drill.

## Storage

`keydrill.db` (SQLite, created on first run): `attempts`, `learning`,
`typing_runs`, `key_stats`. Stop the server and delete it to reset all
progress — removing it while the server is running leaves that process without
its tables until you restart.

## Tests

```bash
python3 tests.py       # 35 end-to-end checks - start the server first
python3 nvimrun.py     # 8 motions through real nvim, including <Esc> and |
python3 decks.py       # loads every deck, prints per-category counts
```

`tests.py` covers the learn engine, skip rotation, multi-answer prompts, answer
checking for every deck, and the submap lifecycle. The submap tests run against
the live compositor rather than a mock, since the failure being guarded against
— a desktop with no working keybindings — only exists there.

## Layout

```
keydrill.py   server, learn engine, scheduling
decks.py      deck loading, categorisation, answer checking
nvimrun.py    headless nvim exercise runner (self-tests: python3 nvimrun.py)
tests.py      end-to-end suite
data/         nvim_motions.json, terminal.json
static/       index.html
.gitignore    excludes keydrill.db, __pycache__, logs
```

`keydrill.db` is deliberately untracked — it holds your personal progress and
is recreated empty on first run.
